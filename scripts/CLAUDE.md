# scripts/

Every workflow is a script here; CI and the nightlies call the same ones. A `scripts/` change runs the `hil-tests.conf` drift check and the device-lock state-machine test in pre-commit; run `bash -n` on an edited script before anything else (a `set -u` crash in a lane leaves `pre-commit` waiting forever with no compiler running).

- **Shared libraries:** `lib.sh` (build helpers, `gradle_lock_run`, `apply_jvm_env`), `lock-lib.sh` (`require_device_lock`), `board-lib.sh` (`resolve_board`, `pin_debug_probe`), `fleet-lib.sh`, `net-lib.sh` (the TCP / HTTP / TLS listeners the `net` rows dial). Source them; do not reimplement.
- **Guards:** `check-source-guards.sh` (twins, cfg gates, the unsafe and panic ratchets, `--layers` via `check-layers.py`), `check-hil-conf.sh`, `check-shrunk-image.sh`, `check-submodules.sh`, `scorecard.py --check`. Each guard has an `--accept` or `--write` that rewrites its baseline; use it in the commit that earns the change, with a trailer (`size:`, `coverage:`).
- **Runners:** `sim-run.sh` (the matrix in the sim, lanes for pdb, GC stress, mem-diag strict, the size ratchet; `--app X --no-pull --no-email` for one row), `hil-run.sh` (one board; reads the conf on fd 3; `probe-rs` with `</dev/null`), `hil-fleet.sh` (every slot), `nightly.sh` (fuzz → sim → fleet at 3 AM, from the live working tree: uncommitted edits run too). Results: `build/{sim,hil,fuzz}/results/`, logs beside them; email via `hil-email.py` with NEW / known / recovered triage.
- **Rows:** `hil-tests.conf` format in its header; no `|` in a pattern; a key-driven sim row pins a board with buttons in the fifth column; `examples/<app>/test.ctrl` drives input; `test.env` sets per-row env (`PICODROID_SIM_FS` isolates LittleFS state from the developer's image).
- **Exit-status plumbing:** `if ! cmd; then rc=$?` stores 0. When a whole class of rows flips PASS → ERROR after a runner edit, diff the runner before the apps.
- **Device scripts** take the lease themselves (`flash.sh`, `pdb.sh`, `power-cycle.sh`, `parity-bench.sh --hil`, `hil-run.sh`); `power-cycle.sh --help` cycles the board. `hil-run.sh` commits `bench/parity/history.csv` unless `PICODROID_BENCH_RECORD=0`.
- **Bulk rewrites:** a count mismatch is evidence the pattern reached somewhere unintended (the `timeout … pdb` rewrite recursed into its own helper); print the matches and read them. Keep refactor edits as re-runnable scripts.
- **Size ratchet:** measure both boards into a scratch dir (`PICODROID_SIZE_RUN_DIR=$D ./scripts/parity-bench.sh --size-only --boards testbench_rp2040,testbench_rp2350`), then `bench-report.py --ratchet --sizes-from "$D" --accept`; park unrelated edits first, the measurement is of the working tree.
- **Release cut:** `pre-commit --full` first; the recipe and its seven files are in `CONTRIBUTING.md`; accept the ratchet as its own commit before the cut so growth stays attributed to the features that spent it.
