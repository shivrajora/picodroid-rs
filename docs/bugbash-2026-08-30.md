# Bug bash — 2026-08-30

A code-wide sweep: three exploration passes (JVM crate, framework core, SDK/shim/tooling)
produced ~45 candidates; each was converted into a failing test or repro app, fixed, or
explicitly closed as not-a-bug. Regression coverage landed alongside every fix — unit tests in
the crate that owns the code, plus two new sim apps (`examples/bugbash`, `examples/bugbash_ui`)
and two stress apps (`examples/threadstress`, `examples/executorstress`) wired into
`scripts/hil-tests.conf`.

Method per bug: write the failing test/app first → confirm red → fix → green → commit
(`[bugbash <id>]` in each message). Ids: `J*` = jvm crate, `F*` = framework core,
`S*` = SDK/collections/Kotlin, `B*` = backlog/stress findings.

## Not a bug (pinned)

- **F12 double-tap double-launch**: two clicks in one tick launching two Activities is Android's
  own behaviour (apps guard it themselves); the historical UAF this would have papered over is
  already prevented by `process_bind`'s `owner_is_live` check. A barrier was prototyped and
  reverted; `bugbash_ui` pins the Android semantics (`creates == 2`).
- **B0 sim atomic-section hooks** (`docs/followups-2026-08.md` §1): `threadstress` — 4 workers ×
  ~131k churn rounds, 23k+ GCs, offensive checks armed — shows no heap-compound interleaving in
  sim. The POSIX-port kernel's one-task-at-a-time guarantee is doing the serialising; hooks are
  not needed for correctness in sim. (Soak evidence: `threadstress` runs clean with
  `PICODROID_MEMDIAG_OFFENSIVE=1 --mem-diag`.)
- **`sb_buf` cross-thread aliasing** (followups §2): already fixed by `896f691` (per-instance
  buffers) before this bash.

## Size

The fixes cost flash: ratchet advanced `+5748 B` (rp2040) / `+6232 B` (rp2350), RAM `+16 B`
(dialog table 4→8). The float formatter deliberately reuses the exact-mode `{:.*e}` path
already linked for `String.format` instead of the shortest-mode `Display` machinery (~2.5 KB
saved); see the `perf(jvm)` commit.
