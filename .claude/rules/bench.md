# The bench: boards, probes, leases

- **One lease per board** (CLAUDE.md §8). `device-lock.sh status` first when a script exits 75; `acquire --board X --wait` with `run_in_background` to queue; `release` when done, and **before** launching a detached `hil-run.sh` or soak (your own session's lease blocks it). `release` with no `--slot` drops every slot the owner name holds and kills that probe-rs: one owner name per detached script.
- **`flash.sh` never exits** (probe-rs streams RTT); run it in the background or detached, redirect to a file, `</dev/null`. It builds the debug profile by default: a later `probe-rs attach` with the release ELF prints nothing. The RTT log is defmt's `Tag: msg`, the sim's is `[Tag] msg`.
- **Never `pkill -f` from a line that will still need to run**, and never with `probe-rs` or a script name on the same line: the Bash tool's whole command text is one process command line, and `pkill -f` matches it (exit 144). Kill by pid, or `pkill -x <exact name>`, in a tool call of its own. `device-lock.sh release` pkills probe-rs by pattern too.
- **Never two APK builds at once** (`sim.sh` + `flash.sh`, two `hil-run.sh` on one slot): the second overwrites the first's PAPK or ELF mid-embed and the board boots `FrameworkVersionMismatch` or a 96-byte image. One runner per slot; `hil-run.sh --board X` uses `build/hil/<slot>/` on a fleet bench.
- **Flash budget:** a HIL row's window is its timeout plus 80 s; the RP2350 images flash in 53–72 s. An empty row log with `MISSING` means the flash ate the window, not the app.
- **Power cycling:** `./scripts/power-cycle.sh` auto-detects the hub; `--help` is not a flag, it cycles the board. The touch kit has a latching soft-power button: a VBUS cycle turns it off until someone presses it, so never cycle `pico_touch_kit` unattended (its fleet row is `cycle=probe`).
- **Wrong-board tells:** a boot log probing another board's peripherals (`psram: nothing answered`, `GT911 did not answer`) is a wrong-firmware flash, not a device bug. `strings <elf> | grep <ssid>` is a false negative for baked WiFi credentials; cargo's fingerprint JSON proves it. `flash.sh` does not read `.wifi-creds.env`; export the two variables for a WiFi check.
- **Faults:** probe-rs catches HardFaults before the handler runs; `--no-catch-hardfault` with the debug ELF makes `[fault] HardFault pc=…` print, then `arm-none-eabi-addr2line -f -C -i`. A `pc` at `__udf` is a Rust panic (grep `panicked at` / `memory allocation of N bytes failed`), not a memory fault. `probe-rs gdb` does not work on these two-core boards.
- **Big allocations on device:** the sim's heap model is the RP2350's and cannot stand in for the RP2040; wrap the global allocator with a stack sweep into `static mut`s and print from the HardFault handler (never log inside `alloc`), or read the words over SWD with `probe-rs read` from the halted board.
- **Detached work:** `setsid nohup CMD > log 2>&1 &` for anything a soak depends on; a `run_in_background` task dies with the session and is capped at 600 s (so is `pre-commit --full` launched that way). Check `pgrep -af 'probe-r[s]'` before reading any number after a resume.
- **Pads a board owns** (display DC, SPI) are refused by `PeripheralManager`; garbage pixels with a clean RTT log was an app taking one. `cfg(debug_assertions)` is off in device firmware of both profiles.
- The bench's probes, slots and boards live in `~/.config/picodroid/fleet.conf`; `./scripts/fleet.sh discover` prints what is plugged in. Reading serials from sysfs, never from `pdb devices`.
